2026-11-08 两个异常素材列由 `lowfrequency_sprite`／`mismatch_sprite` 改名为 `fakecase_1`／`fakecase_2`，可为不同类型组件配置异常外观。现有 `lowfrequency_weight`／`mismatch_weight` 两列分别控制它们的抽取权重，内部状态仍保存为 `lowfrequency`／`mismatch`，性能规则不因字段改名而改变。上下金手指分别接入对应的 `gpu_goldfinger_up/down_wrongcolor` 与 `gpu_goldfinger_up/down_wrongcolor1`，共四张现有图片；坐标、权重保持原值。未配置异常素材的槽应将对应权重设为0。

## 算力和耗电

显存每槽有效值：正常 `1`，低频 `0.6`，错误型号及空槽 `0`。矩形和方形显存合并计数，空槽计入槽位总数。金手指不改变算力和所需能量；任意一组缺失均使显卡无法使用，并可作为质疑项目。

```text
实际算力 = 核心初始算力 × 显存有效值之和 / 显存槽总数
实际耗电 = ceil(核心初始耗电 × 供电模块槽总数 / 有效供电模块数)
```

真实算力以 double 保存在组件状态的 `RealComputePower`，服务器累加时保留小数；提示框最多显示两位小数。原版电池按整数电量结算，所以有效供电时的 `RealPowerPerCycle` 向上取整。所需能量只由核心和有效供电模块数计算，缺供电接口不会令其归零。供电模块全缺时所需能量为0；金手指任一组缺失、供电接口缺失或无有效供电模块均令`PowerSupplyWorking=false`，服务器拒绝工作。旧 `9999` 需求已移除。提示框始终显示算力和所需能量；接口标为缺失时附加淡红提示，正常时不添加“供电接口正常”行。模块全缺另有淡红提示，不替代所需能量行。算力只按核心和显存计算。没有显存槽时算力为零。槽位数量按每张显卡保存的组件表统计，不硬编码 15 或 8。

例如核心初始算力 `100`、耗电 `10`，显存全部正常且两组金手指存在：算力为 `100`；8 个供电模块仅 4 个有效时耗电 `20`，7 个有效时耗电 `12`。

新组件保存 `Condition`（`normal/lowfrequency/mismatch/empty`）以分离状态与素材名称。旧状态只保存素材时，先按注册配置和原版组件素材名补齐语义；组件图及坐标保留。`CoreComputePower/CorePowerPerCycle` 保存首次计算时的核心初始预算，`RealComputePower/RealPowerPerCycle/PowerSupplyWorking` 保存独立真实属性。旧存档首次补齐这些字段时移除原有异常耗电表示。旧数值 Tag 仅保留兼容显示，服务器不回退读取它们。损坏或未知版本的组件状态保留原数据，服务器暂停。

计算使用的槽名具有语义：`memory_` 前缀表示显存，`power_module_` 表示供电模块，`goldfinger_up/goldfinger_down/power_interface` 为对应接口。调位置、素材和权重时保留这些槽名。

## 原生可编辑标签

`GpuLabels` 为每张显卡添加四个 `ItemFeature`：算力、耗电量、供电接口、金手指。它们使用原版 `realCondition/fakeCondition` 和 `ItemConditionList.conditionLookup`，可直接由原版标签机打开并修改。算力选项在0至保存核心最大算力间含两端均分8点；耗电选项在保存核心基础耗电至仅剩一个有效模块的最大耗电间含两端均分8点，取整数并去重，窄区间或零宽区间可少于8项。供电接口与金手指提供正常／缺失两项。真实值、已有标示值和计算器写入的精确数值独立保留，不加入共享下拉选项；耗电选项类别包含上下限，避免不同模块总数互相污染。

默认标示值等于真实值，编辑仅改变 `fakeCondition`。读档修复真实条件并保留标示值、曝光状态；已曝光时按原版规则显示真实条件。`gpu.csv` 的 `computePower` 是显存全部正常时的最大算力；显存全部缺失或错配时最低为0，因此算力颜色标准线为保存的 `CoreComputePower / 2`，即最优与最差的中点。当前可见算力高于标准线用淡绿、低于用淡红、等于用浅青色。`powerPerCycle` 是全部供电模块正常时的最低耗电，仅剩一个有效模块时最差耗电为核心基础耗电×模块总数（与实际计算一样封顶Int32）；耗电标准线取两者平均，低于用淡绿、高于用淡红、等于用浅青色。例如核心耗电10、8个模块，耗电标准线为45。模块数使用保存组件的槽位总数，不使用当前有效数；模块全缺属于供电故障，不把其零耗电当作效率最优值。供电标签显示缺失时追加淡红警告，数字耗电行保留。

服务器通过 `GpuRuntime.TryGetRealPerformance` 仅取独立真实属性快照，忽略四个标签及兼容数值 Tag。即使把真实故障的显卡标为正常/零耗电，训练和生产仍暂停，保留已有进度且不扣电。把正常卡标为缺失也不会改变其实际工作能力。

限定的 `LabelerUIManager.OpenUI` Prefix 在打开原版编辑器前补齐标签和当前语言选项，`CloseUI` Postfix 清除编辑器跟踪；`LabelerHelper.HandleLine` Prefix 仅抑制这四个标签的重复默认行，由 GPU tooltip 统一绘制颜色。禁用时先关闭正在编辑显卡的原生窗口，再只移除本 Mod 仍持有的条件表和分类名，保留其他代码替换的条目。

显卡标签生成后，`OpenUI` Postfix立即重建原生列表布局，按实际标签底部及页脚按钮所需空间向下扩展外框，避免第四项金手指编辑溢出；列表顶部保持原位。关闭、重复打开或切换到其他物品时先恢复原尺寸与位置，不累计增高。原生延迟销毁的旧标签行提前隐藏，避免被计入新列表高度。

## 不诚实卖家、价格与计算器

游戏0.46D，2026-11-05：普通电子卖家和电子拾荒者各有25%的分支改为不诚实版本，货池、件数、价值上限、派系和折扣沿用普通版本。仅在生成所售显卡时独立抽取算力与耗电标签：60%向好、30%真实、10%向坏。向好算力为真实值×1.25、耗电为真实值×0.75；向坏方向相反。真实值为零时浮动仍为零。物理供电接口缺失时另以70%概率标成正常。生成后冻结标签，观察与读档不再次抽取，真实组件与性能不变。

## 单项质疑、结果对话与剩余选项（2026-11-06）
