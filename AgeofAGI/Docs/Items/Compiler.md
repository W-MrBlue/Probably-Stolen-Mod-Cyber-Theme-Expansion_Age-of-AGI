# Compiler（自动编码器）实现说明

2026-11-08 编译预览仅公开组件与基座的属性计算，保留连接算力、反馈训练减免、重复耐久惩罚和正则化耐久加成。除批处理外，架构词条名称及其对算力、内存、耐久、训练量和数据需求的倍率均不计入预览；批处理次数及训练量倍率仍显示。实际编译产物继续冻结全部词条和最终属性，模型物品提示框继续展示完整结果。计算器同次生成独立的预览属性与产物属性，窗口只读取预览属性。

2026-11-07 模型展示：物品统一命名为“未训练的AI模型”与“AI模型”。提示框先列内存、算力、耐久及未训练模型的训练预算，空一行后列任务和逐行词条，再空一行由原版追加物品说明。任务显示名为计算、恶意、感知、生化，后三者分别使用原生LightRed、LightBlue、LightGreen。批处理显示“批处理：N 次/晚”，其他词条显示各项具体乘数；乘数取本次注册加载的编译配置，不在显示代码中另写一套常量。编译预览也将任务与词条移至具体属性之后。提示框实现为 `Logic/AiModel/AiModelTooltip.cs`，模型数值和生产规则不因展示调整改变。

## 架构词条与批处理（2026-11-07，游戏0.46D）

当前基座空间以 `base_model.csv` 为准，Transformer为6×8。编译器将满足条件的架构词条与批处理次数冻结到模型，预览和未训练/已训练模型提示框均显示词条。训练完成、当前格式保存/加载不重新计算原拼图。

| 组件/词条 | 生效条件 | 效果（全模型） |
| --- | --- | --- |
| 残差桥 `part_residual` | 五格C形开口两端各向外延伸一格的两个判定点，分别落在连接器实际选中的同一对编码器与解码器上；不要求接触连接器自身 | 训练量×0.8，内存×1.1，最多一次 |
| 批处理器 `part_batch` | 批处理器通过实际占格四向接触形成连通群；每群收集直接接触的编码器实例并去重，最大群至少两个 | 训练量×1.3，批处理次数为最大群编码器数；多个群不相加，编码器不连接两个群 |
| U型架构 | 编解码器各至少两个，双方全部被一对一连接匹配覆盖 | 性能加成数值×1.5 |
| 重型编码器 | 编码器数>解码器数+2，且有正则化器 | 性能加成数值×0.8，内存×0.5 |
| 高秩架构 | 编解码器各至少三个，每个家族内部ID均不重复 | 耐久×1.5，训练量×1.2 |
| 深度反馈 | 编解码器各至少两个，全部编码器均被一对一反馈匹配覆盖；允许额外解码器 | 训练数据×0.5，训练量×1.3 |
| 重型解码器 | 解码器数>编码器数+2，且有正则化器 | 性能加成数值×1.2，内存×1.4 |

不同效果乘算，同名效果一次。先计算原有连接/反馈收益，再乘架构倍率；性能倍率作用于模型的加成百分比，实际生产倍率仍为 `1 + 加成百分比/100`。内存乘算还包含基座倍率，与训练数据分别在全部乘算后向上取整，耐久在重复惩罚、正则化与高秩倍率全部算完后统一按中点远离零取整。深度反馈仅调整模型训练数据预算，不减少生产材料或抽取的数据量。

新增倍率列集中在 `Data/Definitions/compiler.csv`，每个注册批次读取一次。两个新物品的价格及素材键配置于 `items.csv`，实际占格由各自素材决定，不新增正式供货池。F9可生成 `part_residual`、`part_batch`。

残差桥必须为完整的五格C形，即3×2或2×3矩形中仅缺一条长边的中间格。当前 `part_res` 素材为48×32，占格为上排 `111`、下排 `101`，开口朝下；左上角为 `(x,y)` 时仅检查 `(x,y+2)` 与 `(x+2,y+2)`。旋转、翻转后按实际C形开口定位。凹槽中的空格、C形背部、两侧和对角均不参与判定；两个判定点必须接触双方的真实占用格，而非外接矩形。编码器与解码器可交换两端，但不能用分别属于其他配对的组件凑成残差通路。

普通服务器每晚最多尝试模型批处理次数个配方，无批处理词条时为1。所有尝试共享一个当晚算力预算；完成后把剩余工作量交给下一配方，未完成进度正常保存。每成功交付一批消耗一次AI耐久，最后一次交付后销毁模型；有效工作夜只支付一次硬件电费。输入不足、输出受阻、数据池满或提交失败时结束本夜后续尝试，已完成批次不回滚。

分布式终端上限为 `本夜实际分配的供给服务器数 × 终端AI批处理次数`，不会计入被其他终端占用、正在本地工作或不能供给的服务器。其所有批次共享一份聚合硬件算力乘终端AI倍率的预算，不再每轮重复获得完整聚合算力。训练也只推进一份聚合算力。缸中之脑没有模型槽，不获得编译模型的批处理词条。

独立行为检查覆盖真实匹配残差桥、群连通与去重、最大群、架构边界、最终取整、词条冻结与训练转移、多批次工作守恒、电费/耐久、交付失败及当前格式进度恢复。真实Unity提示框、窗口与存档往返仍需重启后在可丢弃的当前版本测试存档验证。

## 1. 功能与使用流程

Compiler 的物品 ID 为 `age_of_agi.compiler`，中文名称为“自动编码器”。玩家在基座提供的网格内摆放代码组件，点击“编译”，一次生成一个携带计算结果的未训练 AI。

```text
安装基座、电池 → 摆放全部组件 → 查看属性预览 → 点击编译 → 取得未训练 AI
```

编译即时完成，没有进度条，不登记过夜执行回调。当前没有每日编译次数限制；只要重新放入材料且电量、输出空间充足，就可以再次执行。

一次成功编译会消耗网格中的全部组件，包括连接器、反馈器和任务头。基座保留，电池扣除本次耗电后保留。未参与功能配对的组件也会被消耗，其中编解码器仍提供基础属性。

输出物品统一使用 `age_of_agi.ai_untrained`，名称为“未训练的AI模型”；训练后为“AI模型”。任务类型通过属性区后的独立任务行区分。

| 存储索引 | 面板 role | 尺寸 | 用途与限制 |

## 3. 组件与拼图合法性

### 3.1 编码器与解码器

基础组件分别为 `age_of_agi.part_enc_0`～`part_enc_4` 和 `age_of_agi.part_dec_0`～`part_dec_4`。每个组件自身保存基础预测计算性能百分比、内存要求、训练量和独立数据需求。

新建组件的默认数值如下，两个家族使用相同表：

| 数字后缀 | 基础预测计算性能 | 内存要求 GB | 训练量 | 数据需求 |
| --- | --- | --- | --- | --- |
| 0 | +10% | 2 | 40 | 10 |
| 1 | +10% | 2 | 40 | 10 |
| 2 | +10% | 2 | 40 | 10 |
| 3 | +15% | 4 | 80 | 20 |
| 4 | +15% | 4 | 80 | 20 |

编译读取组件实例当前的 Tag，而不是每次从 JSON 获取默认值。连接器、反馈器和任务头的三项基础数值为零，其作用由各自规则提供。

### 3.2 最低要求与拒绝条件

合法拼图至少包含一个编码器和一个解码器；两者编号可以不同，无须直接相邻，也无须填满基座。

计算器检查整个网格。以下任一情况会阻止编译，不会静默跳过对应物品：

- 物品不属于该网格、不是代码组件，或没有对应的组件配置。
- 物品不属于玩家，或某个放置实例的数量不等于 1。
- 编解码器缺少基础属性，或性能、训练量不是有限正数，或内存不为正整数。
- 实际占格为空、超出基座范围，或与其他组件重叠。
- 反馈器不是完整的 4×1 或旋转后的 1×4 直线。
- 连接器不是完整的 2×1 或旋转后的 1×2 直线。
- 缺少编码器或解码器、任务头总数超过一个，或正则化组件超过一个。

组件芯片 `part_enc_chip`、`part_dec_chip` 用于磁盘写入器，不接受进入 Compiler 拼图网格。

## 5. 连接器与反馈器

### 5.1 连接器：提高预测性能

连接器 ID 为 `age_of_agi.part_link`，当前素材32×16，实际占格2×1，旋转后为1×2。与反馈器使用同一套短边端点判定：只检查两条短边外紧邻的两个格子，一端必须是编码器，另一端必须是解码器，方向可交换。

横放连接器左上角为 `(x,y)` 时，检查 `(x−1,y)` 与 `(x+2,y)`；竖放时检查 `(x,y−1)` 与 `(x,y+2)`。长边和对角接触均不生效；端点必须落在编解码器实际占用的格子上，不能仅接触外接矩形。旋转和翻转后按实际方向判断。

每个连接器最多提出一对候选，双方形状编号无需相同。每个成功配对的基础组件，其性能百分比贡献乘 `linkComputeMultiplier`，当前为 `1.2`。例如 +10% 与 +20% 的组件配对后分别贡献 +12% 和 +24%。多个连接器仍执行全局一对一匹配，同一基础组件仅受链接一次；残差桥与U型架构继续读取实际选中的配对。

### 5.2 反馈器：减少训练量

反馈器 ID 为 `age_of_agi.part_feedback`，实际占格为 **4×1**，旋转后为 1×4。

它只读取两条短边外紧邻的格子。必须一端为编码器、另一端为解码器，编号不限；长边和对角接触不生效。

```text
编码器占格 │ 反 │ 馈 │ 组 │ 件 │ 解码器占格
            ← 反馈器占用四格 →
```

若横放反馈器左上角为 `(x, y)`，两个判定格为 `(x−1, y)` 和 `(x+4, y)`；竖放时为 `(x, y−1)` 和 `(x, y+4)`。旋转和翻转后按实际方向判断。

配对成功后，两者各自贡献的训练量乘 `feedbackTrainingRetention`，当前为 `0.8`。它不减少数据需求或内存要求，也不直接增加预测性能或耐久。

### 5.3 多个功能组件如何分配

连接与反馈分别建立候选配对，使用最大权重二分图匹配，使参与配对的基础算力总和最大。共享候选可以重新分配，避免先遍历的功能组件抢占组件、降低总收益。

每个基础组件在连接匹配中最多出现一次，在反馈匹配中也最多出现一次；同一个组件可以同时获得一次连接加成和一次反馈减免。反馈配对同样按基础算力选择，不以节约的训练量作为权重。

算力相同时，使用网格位置与物品 ID 形成稳定的处理顺序，避免结果依赖物品放入顺序。功能组件没有配对成功时不提供收益，但仍随整张拼图消耗。

## 6. 未训练 AI 的六项属性

令第 `i` 个基础组件提供性能百分比点 `Pᵢ`、训练量 `Wᵢ`、内存 `Mᵢ`，并定义：

```text
Lᵢ = 已获得连接加成时取 1.2，否则取 1
Fᵢ = 已获得反馈减免时取 0.8，否则取 1

预测计算性能百分比 P = Σ(Pᵢ × Lᵢ)
预测计算性能倍率     = 1 + P / 100
训练量 W             = Σ(Wᵢ × Fᵢ)
数据需求 D           = Σ(组件实例的 trainingData)，不受反馈减免影响
内存要求 GB          = Ceil(ΣMᵢ × 架构内存倍率 × 基座内存倍率)
预测初始耐久 D       = 四舍五入(10 × 0.9^R × 正则化倍率)
正则化倍率           = 存在正则化组件时取1.2，否则取1
```

其中 `R` 为重复组件总数。按“编码器/解码器家族＋数字后缀”分组，每组从第二个开始累计：

```text
R = Σ max(同组数量 − 1, 0)
```

例如，三个 0 号编码器与两个 0 号解码器，重复总数为 `(3−1)+(2−1)=3`，耐久为 `四舍五入(10×0.9³)=7`；增加正则化后为 `四舍五入(7.29×1.2)=9`。无重复且有正则化时为12。一个 0 号编码器和一个 0 号解码器属于两个家族，不触发重复惩罚。旋转和翻转不改变数字形状身份。

训练量和性能百分比保留浮点值；组件内存累加后经架构与基座乘数计算，最终向上取整为整数 GB。耐久在全部乘算完成后四舍五入，中点远离零，不逐步取整；Tag仍以float保存整数值。训练成品继承该值，不再次施加正则化加成。

## 7. 执行与耗电

单次耗电读取机器实例的 `MACHINE_POWER_PER_CYCLE` Tag，新建 Compiler 的配置初始值为 **10**。每张拼图统一使用该成本，不因组件数量或是否存在连接器而切换耗电配方。

点击后的主要执行顺序是：

1. 重新计算整张拼图，检查基座、基础组件、任务头和布局。
2. 检查电池存在、归玩家所有，且能支付机器当前单次耗电。
3. 创建临时未训练 AI，写入五项属性及版本，再构造原版 `CraftingRecipe`。
4. 将全部组件声明为消耗材料，电池声明为按本次成本扣电的工具。
5. 检查输出能否容纳产物，并先将指定产物放入输出区。
6. 再次检查电池、基座、组件实例、位置、朝向、属性、机器耗电和产物所在输出区，确认计算结果未改变。
7. 调用原版 `Craft` 扣除材料和电量，刷新电池外观与机器状态。

材料、电量或输出放置检查失败时，不执行资源扣除；未提交的临时产物会被销毁。此处使用原版配方处理材料和带电工具，没有额外登记每日自动耗电。

`busy` 防止执行回调重入，`refreshing` 防止状态刷新递归。输出区只在内部转移指定产物实例时临时开放，普通玩家或自动化不能往输出区放入其他物品。

## 8. 配置入口

所有路径以 `Modding/AgeofAGI/` 为根。配置在物品目录注册批次中加载并校验，创建实例和编译时不反复读取配置文件。

| 文件 | 负责内容 |
| --- | --- |
| [Data/Definitions/compiler.csv](../../Data/Definitions/compiler.csv) | 单一整网格配方、产物、初始耐久、重复惩罚、连接、反馈与正则化系数 |
| [Data/Definitions/ai_parts.csv](../../Data/Definitions/ai_parts.csv) | 组件角色、基础属性、任务头类型 |
| [Data/Definitions/machines.csv](../../Data/Definitions/machines.csv) | Compiler 新实例的单次耗电初始值 |
| [Data/Definitions/base_model.csv](../../Data/Definitions/base_model.csv) | 各基座提供的网格宽高与模型内存乘数 |
| [Data/items.csv](../../Data/items.csv) | 物品 ID、kind、初始图片、价格和语言键 |
| [Localization/zh.csv](../../Localization/zh.csv)、[en.csv](../../Localization/en.csv) | 组件与任务名称、属性行、预览和失败提示 |

### 8.1 Compiler 配方

```json
{
  "recipes": [
    {
      "id": "compile_assembly",
      "output": "age_of_agi.ai_untrained",
      "initialDurability": 10,
      "duplicateDurabilityRetention": 0.9,
      "linkComputeMultiplier": 1.2,
      "feedbackTrainingRetention": 0.8,
      "regularizationMultiplier": 1.2
    }
  ]
}
```

当前要求 `recipes` 恰好一条。`initialDurability` 为有限正数；两个 retention 在 `(0, 1]`，连接和正则化倍率为有限数且至少为 1。原来的 `power`、`requiresLink` 字段和 linked/basic 优先级分支已经移除，旧字段会被严格解析器拒绝。

### 8.2 组件配置

每条配置包含 `id`、`role`、`computeBonusPercent`、`memoryGb`、`trainingWork`、`trainingData`、`taskType` 七个字段。基础组件的 `trainingData` 为正Int32，功能组件为0；它与训练工作量独立配置。`role` 支持 `encoder`、`decoder`、`link`、`feedback`、`task_head`、`regularization`。

编解码器的 ID 必须具有相应家族前缀和数字后缀，三项基础属性必须为正，`taskType` 为空。功能组件三项基础属性为零；任务头的 `taskType` 为受支持的任务标识，其他角色为空。任务头类型集合在 `AiTaskTypes` 中定义，新增全新任务类型还需要更新该集合和本地化。

组件 JSON 与 CSV 的 `kind=ai_parts` 物品双向校验；源芯片不属于这份参数表。价格统一放在 CSV 的 `base_value`，不放入类别 JSON。

模型的业务属性保存在自身 Tag 中：

| Tag | 类型与含义 |
| --- | --- |
| `AGE_OF_AGI_AI_MODEL` | 模型家族标记 |
| `AGE_OF_AGI_AI_ATTRIBUTES_VERSION` | 整数，未训练模型属性版本为2，必须携带独立正数训练数据预算 |
| `AGE_OF_AGI_AI_TASK_TYPE` | 字符串，稳定任务类型标识 |
| `AGE_OF_AGI_AI_TRAINING_WORK` | 浮点，训练量 |
| `AGE_OF_AGI_AI_TRAINING_DATA` | 正Int32，独立总数据需求，版本2模型必填 |

生成时只写入模型所需字段，不复制输入的所有权、锁定、机器或组件专用状态。`GetPredictedComputeMultiplier` 将保存的百分比换算为 `1 + 百分比 / 100`。

## 10. 存档与版本兼容

编译成功时，六项属性固定保存在产物中。读档只恢复这些值并更新任务名称，不根据当前基座、原始组件或新配置重算已有模型。训练模型必须有独立正数数据需求，不提供旧费率或历史任务转换。详细训练公式见 [Training.md](Training.md)。

组件读档时只补齐缺失的基础属性，不覆盖已有实例数值。机器同样保留已保存的耗电，仅在耗电 Tag 缺失时使用配置初始值。因此，修改 `machines.csv` 为 10 不会自动把旧机器保存的 5 改成 10。

旧版生成的 AI 如果没有完整编译属性，不会被自动填入推测的训练量和性能。当前 F9 的 `Spawn ai_untrained` 会单独写入 `ModDebugActions.cs` 中配置的调试属性；Compiler产物仍由组件计算。服务器 S01 训练现已实现，完成时原值继承任务、内存、预测性能与耐久，详见 [Serverbox 说明](Server.md)。

反馈器的新建占格与素材均为 4×1。早期版本保存的 3×1 覆盖会在读档时恢复为 4×1，保留位置、旋转与翻转；该处理不会自动重排邻近物品。若旧布局因此重叠或越界，需要调整后再编译。

## 11. 常见提示与读档问题

| 提示或现象 | 检查方式 |
| --- | --- |
| 请安装基座 | 检查基座是否存在、归玩家所有且数量为 1 |
| 至少需要一个编码器和一个解码器 | 检查是否误放了源芯片，或只放入同一家族组件 |
| 组件属性或布局无效 | 检查实例数量、基础属性、实际占格、重叠、越界和组件配置 |
| 最多只能安装一个任务头 | 总共只保留一个任务头，同类也不能重复 |
| 最多只能安装一个正则化组件 | 只保留一个正则化组件，可与任务头同时使用 |
| 电量不足 | 检查电池、电量及该机器实例当前单次耗电 |
| 输出空间不足 | 腾出足以容纳完整产物的连续占格 |

原版 `GeneralHelper.IsItemOwned` 不接受空值。读档会先创建空机器再恢复子物品，因此刷新与执行路径均在调用该方法前判断电池是否存在；无电池创建、读档或取出电池都应正常保持空闲。

早期漏判空曾造成 `CompilerRuntime.RefreshState → GeneralHelper.IsItemOwned` 的空引用异常。游戏的 `EmporiumEntry.Start` 在读档前暂停全局音频，完成后才恢复，加载异常会使恢复代码无法执行，表现为读档后缺声。应先解决加载异常并完整重启游戏再读取，不能仅强制恢复声音来替代完成加载。

## 12. 构建与验证

从工作区根目录运行：

```powershell
dotnet build .\Modding\AgeofAGI\Aoa.csproj -c Release
dotnet run --project .\Modding\Tests\ItemCatalogChecks\ItemCatalogChecks.csproj -c Release
```

构建成功会将 DLL、配置与运行资产复制到 `Mods/AgeofAGI/`。仅修改源配置不会自动更新游戏；部署后需重启游戏。已有还原结果可用时，可给命令增加 `--no-restore`。

[CompilerChecks.cs](../../../Tests/ItemCatalogChecks/CompilerChecks.cs) 与 [CompilerBaseChecks.cs](../../../Tests/ItemCatalogChecks/CompilerBaseChecks.cs) 覆盖目录校验、基座尺寸与锁定、空电池生命周期、整网格消耗、最高收益配对、反馈四向旋转、重复耐久、任务头冲突、预览、失败守恒、重入和重建窗口绑定。检查使用独立生成的图片样例及原版 `CraftingRecipe`、过滤器源码，场景、UI、库存仍有测试替身。

游戏内手动验证应包括：放入和取出电池、不同基座、连接与反馈布局、同形重复、任务头冲突、满输出、低电量，以及携带组件和编译产物的真实存档往返。自动检查不能证明 Unity 显示、原生排布或真实存档恢复全部正确。

原版 API 与开发经验见 [AgentModdingGuide.md](../../../../AgentModdingGuide.md)，其余物品注册约定见 [README.md](../../Items/README.md)。
